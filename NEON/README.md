# GF(2)[x] Polynomial Multiplication on NEON

This directory contains code for generating and benchmarking optimized implementations of polynomial multiplication over GF(2)[x] using SIMD instruction sets, targeting NEON on ARMv8 processors.

---

## Structure

```
NEON/
├── GFmulOpt_NEON/   # Code generator for optimizing GF(2)[x] multiplication
├── hqc_opt_NEON/    # HQC integrated with our GF(2)[x] multiplication
├── bike_opt_NEON/   # BIKE integrated with our GF(2)[x] multiplication
└── enable_ccr/      # Utility to enable access to the ARM cycle counter (PMCCNTR_EL0) for cycle-accurate benchmarking
```

---

## Requirements

An ARMv8 CPU with NEON instruction support (e.g., Raspberry Pi 4)

---

## Build and Run

### 0. enable_ccr
>IMPORTANT: This step must be completed first before running any benchmarks in the following sections (1, 2, and 3).

This directory provides a utility (from rdolbeau/enable_arm_pmu) to enable user access to the ARM PMU cycle counter (PMCCNTR_EL0), which is required for cycle-accurate benchmarking on ARMv8.

To install:

```bash
cd enable_ccr
make install
```
Source: https://github.com/rdolbeau/enable_arm_pmu
### 1. GFmulOpt_NEON
#### 1) Optimize GF(2)[x] multiplication

Run the optimizer to search for the best multiplication algorithm for each degree:

```bash
cd GFmulOpt_NEON
make gfopt
./gfopt_NEON
```

This will generate benchmark files in `src/` (e.g., `gfopt_len_2.c`, `gfopt_len_3.c`, ...), each of which tests polynomial multiplication algorithms for a specific dimension.

You can tune the optimization via `gfopt.h`:
- `N_TEST` : Number of iterations for performance testing
- `MAX_LEN`: Maximum polynomial degree to optimize

To reset before re-running:

```bash
make clean
```

#### 2) Generate multiplication code

To generate code for specific degrees (e.g., 70, 141, 226):

```bash
make gfopt_codegen
./gfopt_codegen 70 141 226
```

Generated code will appear in the `result/` directory.

### 2. hqc_opt_NEON

This directory contains code that integrates our optimized implementations of polynomial multiplication over GF(2)[x] on NEON into the HQC.

To evaluate performance, move into the directory and run:

```bash
make test_speed_all
make run_tests
```

These commands will build and run the following tests:

(1) NEON baseline (ported HQC reference): HQC reference implementation ported to NEON (Neon-VMULL_P8) by Ming-Shing Chen et al.  
(2) GFmulOpt-integrated HQC (ours): HQC integrated with our NEON-optimized GF(2)[x] polynomial multiplication generated by GFmulOpt.  
(3) Additive-FFT HQC (Chen et al.): HQC implementation using the Additive-FFT approach proposed by Ming-Shing Chen et al. in “Accelerating HQC with Additive FFT (Cryptology ePrint Archive, 2026)”.

To build individual tests manually:

```bash
make test/test_speed               # (1)
make test/test_speed_gfopt         # (2)
make test/test_speed_AFFT          # (3)
```
	@echo "\nRunning test/test_speed..."
	@./test/test_speed
	@echo "\nRunning test/test_speed_gfopt..."
	@./test/test_speed_gfopt
	@echo "\nRunning test/test_speed_AFFT..."
	@./test/test_speed_AFFT

To run them individually:

```bash
./test/test_speed                  # (1)
./test/test_speed_gfopt            # (2)
./test/test_speed_AFFT             # (3)
```

### 3. bike_opt_NEON

This directory contains code that integrates our optimized polynomial multiplication into the BIKE post-quantum cryptographic scheme using NEON.


To build and run a test, configure it using `cmake` options:

```bash
cmake -DCMAKE_BUILD_TYPE=Release -DCMAKE_C_FLAGS="-DLEVEL=<1|2|3> -DGFMUL_VER=<0|1|2|3>" ..
make
./bike-test
```

- `LEVEL`:
  - `1`: BIKE security level 1
  - `3`: BIKE security level 3
  - `5`: BIKE security level 5

- `GFMUL_VER`:
  - `0`: Original multiplication in BIKE
  - `1`: Original multiplication in BIKE using NEON-based base multiplication  
  - `2`: Our proposed method

--Example--  
To run BIKE security level 3 with our optimized method:

```bash
cmake -DCMAKE_BUILD_TYPE=Release -DCMAKE_C_FLAGS="-DLEVEL=3 -DGFMUL_VER=2" ..
make
./bike-test
```
